## 4. 验证方式（正式期）

练习期的 CDP 无头验证随 Web 路线作废，Godot 时代的等价物如下。
**日常入口是一条命令**（不要手敲长命令，见 §4.7）：`node tools/verify.mjs 06`。

### 4.1 加载验证（已实现，基线成立）

`--headless --path <proj> --import`（只导资源，不跑场景）→ `--headless --path <proj> --quit`
（加载主场景后立即退出，会执行 `_ready()`）。**两者都 EXIT=0** 且日志 grep
`error|warning` **命中 0 条**才算工程干净。必须用 `_console` 版，Standard 版不向终端输出脚本报错。

实测复核（2026-09-26）：`4.7.2.stable.official.ed1daf0bf`，两条命令均 EXIT=0，日志零命中。

### 4.2 逻辑验证（sim 层单元测试）

`sim/` 只放**纯 GDScript、不碰场景树、不碰物理 API** 的逻辑：武器数值表、波次强度曲线、
AI 决策、资源循环。框架用 **GUT**（`addons/gut/`，MIT）：

```bash
$GODOT --headless --path projects/06-mech-fps -s addons/gut/gut_cmdln.gd \
       -gdir=res://sim/tests -gexit
```

`-gexit` 把失败转成非零退出码，供 `verify.mjs` 判定——这是「DoD：sim 断言全绿」的可执行形式。

### 4.3 流程验证（bot 统计断言，**不是**逐帧回放）

**练习期的「确定性输入回放」在 Godot 下不成立**，必须改口径。原因：角色移动交给第三方控制器
（Jeh3no 模板）+ Godot Physics（`CharacterBody3D` / `move_and_slide`），PhysicsServer 不保证
跨次运行逐帧一致，种子 RNG 也管不住它。

改为**统计断言**：bot 只注入输入序列，不校验中间帧，断言**结果分布**——通关率、TTK 分位数、
受击频率、资源净收益。同参数跑 N≥10 次取分位数，基线判定看**区间**而非单值。
凡逐帧可比的部分（伤害结算、换弹计时、波次推进、AI 状态转移）一律搬进 `sim/` 由 §4.2 覆盖。

第一步地基已落地（06，2026-09-27）：

- `tools/smoke_battle.gd` —— 真的加载主场景、真的出怪、真的开枪打死敌人、真的判死结算，
  20 条断言，`node tools/verify.mjs 06` 的 `smoke` 步骤。它抓到的三个真 bug（信号名写错导致
  装配层静默没跑、敌人在进树前设 `global_position`、敌型碰撞体中心偏移导致射线打空）
  都只可能在运行时暴露，`--headless --quit` 那种「能开机」级验证看不见。
- `sim/match_sim.gd` + `tools/sim_report.gd` —— 抽象整局的**跑分**：三种玩家画像 × 多seed，
  产出通关率/时长/累计受击/弹药自给的**分布**，`verify.mjs` 的 `balance` 步骤与
  `sim/tests/test_match_sim.gd` 把它锁成区间断言（龟缩必败、普通险胜、高手从容）。
  这一层完全不碰引擎，所以同种子必然同结果，可以精确断言——这正是把「逐帧可比的部分下沉 sim」
  这条分工线兑现掉的地方。

> 不要试图在 Godot 里复现练习期 Node 端的完全确定性——那是弃 three.js 的最大代价之一，
> 本路线图已明确接受，别再重复踩。

### 4.4 画面验证（**必须有窗口**，headless 截不出图）

`--headless` 走 dummy 渲染驱动，**不产生任何画面**，
`get_viewport().get_texture().get_image()` 只会拿到空图。旧文档「`--headless` 截图」的说法是错的，已纠正。

正确做法二选一：

1. 有窗口运行 + 一次性截图脚本：延迟 N 帧后
   `get_viewport().get_texture().get_image().save_png(path)` 再 `get_tree().quit()`；
2. `--write-movie`（需本机 FFmpeg）产出视频，供人眼验手感与氛围的连续性。

截图落 `_scratch/shots/`（已 gitignore）。**手感与「好不好看」不可自动化，由制作人本人验收。**

### 4.5 人验占比是本作性质决定的，不是工程缺陷（2026-09-26 接受）

06 的 DoD 第 1 条「移动手感通过人验」只能由用户本人打分。验证脚本证明的是「没崩」，
永远不证明「好玩」。已接受这一事实，并保留 §6 的退路：若 06 长期卡在手感，
可先切 2D 横屏拿下一个「全自动验证 + 精美」的完整作品，再回攻 movement FPS。

### 4.6 耗时类指标

FPS 在 headless 下不可信（沿用练习期教训）。规模结论只看 draw call / 面数 / 节点数。
验证前实测渲染后端，不要假设。

### 4.7 入口脚本

`tools/verify.mjs <编号>` 一条命令跑完当前工程的全部可自动化检查，任一环节失败即整体非零退出：

| 步骤 | 内容 | 对应小节 |
|---|---|---|
| `import` | 资源导入，ERROR/WARNING 必须 0 | §4.1 |
| `load` | 加载主场景后退出（会跑 `_ready`） | §4.1 |
| `sim-tests` | GUT 跑 `sim/tests`，断言失败 → EXIT=1 | §4.2 |
| `assets` | 模型动画/包围盒实测复核 | §4.1 衍生 |
| `smoke` | 战斗闭环冒烟（出怪/命中/击杀/结算） | §4.3 |
| `balance` | 整局跑分：三画像通关率与时长分布 | §4.3 |
| `waves` | 波次曲线预览（时长是否在设计区间） | §4.3 |

已在表格里**显式标注排除**而不是静默放宽，详见 §5.0b 第 7 条。

## 5. 已沉淀的技术教训

### 5.0 Godot 工程初始化（2026-09-26 实测，06 工程建立时）

1. **`InputMap.add_action()` 不持久化**。Godot 4 的 InputMap 是内存结构，`add_action()`
   不会回写 ProjectSettings——即便随后调 `ProjectSettings.save()`，project.godot 里也
   **一个动作都没有**，`InputMap` 的改动随进程退出丢失。正确写法是
   `ProjectSettings.set_setting("input/" + name, {"deadzone": 0.2, "events": [InputEvent...]})`
   再 `save()`。**验证必须 grep project.godot**，别信脚本自己的「保存成功」打印
   （save() 返回 OK 但内容没变，就是这个坑）。
2. **`addons/` 目录不要改名**。模板的 `.tscn/.tres/.uid` 内嵌 `res://addons/<原名>/` 引用，
   改名要同步改所有引用文件。保持模板原目录名，只在文档里说明「这是什么」。
3. **第三方模板的 typo 要照抄**。Jeh3no 模板 `move_left_action = "play_char_move_left_ation"`
   （少了 c，见其 `player_character_script.gd:142`）。模板内部三处引用自洽
   （export 默认值 / default_input_actions 字典 / input_actions_list），
   所以注册 InputMap 时**必须用错名**，否则该键仍走运行期兜底分支并刷警告。
4. **`unzip -t` 必做**。本机断流会产出「看起来下完了」的半成品：particle-pack 断在
   1.98 MB（unzip -t 失败），完整包是 **15.0 MB**。`curl -C -` 能从半成品续传。
   教训：**文件大小本身就是完整性信号**——同站同类型包差一个量级时，先怀疑断流。
5. **`--import` 与 `--quit` 是两件事**：`--import` 只做资源导入（不跑场景），
   `--quit` 才加载主场景。两者都 EXIT=0 才算工程干净；只跑 import 会漏掉 `_ready()` 里的运行期问题。
6. **脚本模式下新建的 `InputEventKey` 会序列化出 `device:16`**，应改成 `-1`（任意设备）。
   手写/批量替换时检查这个字段。鼠标同理：`InputEventMouseButton` 也要显式 `device = -1`。

### 5.0b Godot 4.7 编写期踩坑（2026-09-27，06 战斗层落地时）

1. **`create_timer()` 不在 Node 上**，属于 SceneTree。写成 `create_timer(1.0)` 直接
   `Parse Error: Function "create_timer()" not found in base self`；要写 `get_tree().create_timer()`。
   （`create_tween()` 倒确实是 Node 的方法，两者不对称，容易记混。）
2. **`:=` 从 Variant 推断会当错误处理**。本工程把 unsafe 类型推断警告升级为错误，所以
   `var x := dict["k"]`、`var t := array.pop_front()` 这类**必定编译失败**，
   必须显式写 `var x: String = dict["k"]`。从 Dictionary/Array 取值一律带类型标注。
3. **`Engine.get_version_info().major` 不能用 `:=`**（同上，Dictionary 属性访问是 Variant）。
4. **模板场景的 `ext_resource path` 前缀是原仓库目录名**（`res://Godot-Advanced-State-Machine-...`），
   我们能正常加载是因为 `.uid` 一起拷了过来、Godot 优先按 UID 解析。
   **结论重申：addons 目录名与 `.uid` 文件都不能动**（§5.0 第 2 条的延伸）。
5. **GUT 全绿时只打 `Asserts 430`，有失败才打 `Asserts 416/428`** —— 解析输出的正则必须兼容两种形态，
   否则「断言 ?」会让人以为测试没跑。
6. **脚本模式的 `@tool extends SceneTree` 必须显式 `quit()`**，否则 `--headless` 进程永不退出。
   我这次写 `tools/preview_waves.gd` 漏了它，白等 5 分钟还被误判成「脚本卡死」。
   判据：任何 `-s res://tools/*.gd` 的脚本，最后一行必须是 `quit(code)`。
7. **退出时的「收尾噪音」要按步骤显式排除，不能全局静默**。实测：`smoke`（脚本模式）与
   `load`（`--quit`）**各报 2 条** —— `2 ObjectDB instances were leaked` + `1 resources still in use at exit`。
   来源是引擎退出顺序：场景里已启动的 tween 还没跑完、被 ResourceCache 抓住的 MP3 资源没释放，
   与被测逻辑无关（判据：把冒烟测试的收尾等待从 0 帧加到 230 帧，泄漏从 **6/3 降到 2/1**，
   说明大头确实是未落地计时器，剩下的是引擎层噪音）。
   处理方式：`tools/verify.mjs` 把这两类行**单独计数并始终打印**，只有显式声明
   `ignoreTeardown` 的步骤才排除（目前只有 `load` 与 `smoke` 两个「加载即退出」的步骤），
   业务层 ERROR/WARNING 仍必须为 0。加 `--verbose` 时这两行不出现，别据此判定「修好了」。
8. **协程里的局部变量会活到函数结束**。`_initialize()` 里 `load(...)` 得到的 PackedScene
   因为函数还没返回而一直被引用，导致退出时报「resources still in use」；
   把载入挪进独立函数（`_load_main()`）返回实例，引用就能及时释放。

### 5.0c Godot 4.7 2D 与着色器实测踩坑（2026-09-27，08 M0/M1 落地时）

全部是**运行期才爆**的错（`--headless --import` 不报，因为导入不跑脚本），
每条都在 08 的首轮真跑里付出过一次返工：

1. **枚举改名**：`Environment.BG_CUSTOM_COLOR` 不存在（那是 3.x 的名），4.x 用 `BG_COLOR`。
2. **属性名单复数陷阱**：`env.adjustments_enabled` 错，正名 `adjustment_enabled`（单数）。
   写错不报编译错，只报「Invalid assignment of property or key」运行期错。
3. **`Environment.glow_levels` 不能直接赋 PackedFloat32Array**（Invalid assignment），
   要改就逐元素改，或者干脆用默认曲线。
4. **`Sprite2D` 的分帧属性是 `hframes` / `vframes`**（无下划线），
   写成 `h_frames` 是 AnimatedSprite2D 的思路，运行期报属性不存在。
5. **GDScript 没有全局 `dot()`**（只有 `Vector3.dot()` 方法），但**着色器里有**（GLSL 风）。
   两边写法不一致，很容易记混。
6. **`const P := MovementParams` 非法**：报「Assigned value for constant isn't a constant expression」
   （类名不是常量表达式）。要当命名空间用就 `const P := preload("res://sim/xxx.gd")`。
7. **着色器老式提示语法在 4.7 被拒**：`uniform float x = 1.0 : hint_range(0.0, 1.0)`
   报「SHADER ERROR: Expected expression, found: HINT_ENUM」，**整个 shader 编译失败**。
   最稳的对策：lab/工具类 shader 一律不挂 hint，参数由 `set_shader_parameter()` 传。
8. **`fragment()` 里不能用 `return`**（「Using 'return' in the 'fragment' processor function is
   incorrect」），只能单出口 if/else 组。
9. **脚本模式 `add_child()` 后立刻 `get_node()` 会拿到 null**：代码在 `_ready()` 里造的
   子节点要等一帧。同时**必须用 `get_node_or_null()` + 空值即失败**，否则后续断言
   全部因运行期错被跳过，最后打印「零失败 = 全部通过」（本仓 08 冒烟测试真发生过）。
10. **冒烟测试的断言口径要贴设计口径**：测「满跳高度」时中途 `action_release` 会触发
    jump cut，量到的是短跳；测「二段跳更高」时基线要从地面起算。
    三条失败里有两条是测试自己错的，只有一条（墙跳把玩家往墙里顶）是真 bug——
    但**没有这个测试就碰不到那个真 bug**。

### 5.4 仓库卫生（2026-09-26 审查后新增）

1. **行尾**：本仓库现存文本文件**全部是 CRLF**（Windows 原生写入，`core.autocrlf=false`）。

### 5.6 Godot 载具足球踩坑（2026-09-27，07 工程建成当天）

1. **`PackedScene.pack()` 序列化三连坑**（build 工具生成场景时全中）：
   ① `owner` 必须**递归**设到每个层级——只设直接子节点会让所有孙节点
   （碰撞形状！）静默丢失，球场变「空壳」，车和球全部自由落体；
   ② 运行时 `add_to_group()` **不序列化**——分组挪到运行期脚本 `_ready` 里补；
   ③ `set_meta()` 同样不序列化——节点身份信息（pad 大小/球门归属）从节点名推导。
2. **Godot 4.7 的 `VehicleBody3D` 正 `engine_force` 沿本地 `+Z` 推进**（实测：车朝
   预期反方向开）——不是文档直觉的 `-Z`。转向轮要选本地 +Z 端的两轮（选错端 =
   后轮转向，画龙搁浅）。模型朝向用 `MODEL_YAW_DEG` 常量对齐并留截图复核。
3. **自定义 RNG 的方法名别撞 Godot 内置 utility**（`randf`/`randf_range`）：类内
   **裸调用**会解析到全局内置（进程随机），显式 `r.randf()` 才走成员——确定性被
   静默击穿且只有部分路径中招，极难排查。取 `unit()`/`frange()` 这类名字。
4. `VehicleWheel3D` 的半径属性叫 **`wheel_radius`**（不是 `radius`）；用
   `global_transform` 算轮径时注意别把模型缩放（KART_SCALE）乘两次——重复缩放
   会把轮子放大 2.5 倍扎进地里，悬挂够不着地，整车失去驱动。
5. **Area3D 的 `body_entered` 回调里改 `monitoring` 会被引擎拦截**
   （`Function blocked during in/out signal`），必须 `set_deferred`。
6. **Poly Pizza 的 GLB 尺度可能是百万米级且带巨大偏移**（球模实测 106 万米、
   偏移 37 万米）——运行时量 AABB 自动缩放 + 回中，换模零改动。
7. **Godot 4.7 restitution 合成 ≈ 取两侧较大值**（探针实测梯度），非 Rapier 的
   Average；高速撞击有 solver 损耗（标称 0.9 → 实测 e≈0.86）。
8. **冒烟测试与「自由滚动的真实球」共存时，固定等待全部不可靠**——测试球会自己
   滚进球门（真实进球）把相位拖走。相位断言一律轮询状态迁移 + 超时；直线测试前
   先把开球球挪到角落，隔离真实碰撞体。更彻底的做法：驾驶类回归先 `restart()` 等
   进 PLAYING 后 `director.set_physics_process(false)` 暂停规则，纯物理跑完再恢复。
9. **速度帽只能拦「同向加速」，绝不能拦反向油门**（07 制作人实测操作锁死教训）：
   「速度 ≥ cap 就跳过整个引擎力」会让满速时 S 刹不了车、boost 后全部输入失效；
   「倒行中按 W 被额外拦截」更是直接滑行到撞墙。正确姿势：油门方向与运动方向
   相反（刹车/纠偏）无条件放行，同向加速才受帽限制；倒挡另设低帽（10 m/s）。
