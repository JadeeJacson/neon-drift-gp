## 0. 先立规矩：能玩 / 好玩验收清单

**沿用 04 / 03 验证过的制度：验收清单先于架构。** 体素沙盒被删 = 「技术全绿但不好玩」。本选型最该警惕的正是这一点——**第一人称足球的操作天然别扭**（看不到自己的脚、球在脚下容易丢视野），如果控球手感没做出来，就是下一个被删的项目。

### 「能玩」验收（M1 必须全过，做不完不许进 M2）

- [ ] **第一人称视角成立**：PointerLock 转视角，WASD 移动，重力落地，不穿墙 / 不卡墙角（复用 04 KCC）
- [ ] **踢球有反馈**：踢球动作 + **踢球音** + 球可见飞行轨迹 + 触球判定（近身自动吸附 / 按键踢）
- [ ] **球物理可信（拟真）**：球会弹跳 / 滚动 / 撞墙反弹 / 最终能停；不穿地、不飞天、无 NaN
- [ ] **能进球**：把球踢进对方球门 → 进球判定 + **进球音** + 比分 + 重开球（kickoff）
- [ ] **有对手**：至少 1 个 AI 会追球 / 带球 / 射门；玩家能丢球也能抢断
- [ ] **有胜负**：定时或进 N 球结束 → 结算面板；一键重开

### 「好玩」验收（M2–M3 目标）

- [ ] **控球手感成立**：球能贴脚带（不黏死、不飞太远），传球 / 射门力度可控（蓄力条）
- [ ] **弧线球（香蕉球）可做**：旋转产生可见弧线（Magnus）
- [ ] **对手有可读行为**：追球 / 卡位 / 回防 / 射门，不是站着等球的木头
- [ ] **技巧空间**：挑射 / 弧线 / 抢断时机 / 跑位，不是无脑冲
- [ ] 单局 **3–6 分钟**，死亡 / 失球后 **< 2 秒**可重开（低挫败、高重试）

### 验证四轨（复用 04 体系）

1. **确定性回放**：同输入步进 N 次末态一致（04 已证 `src/sim` 可 Node 直跑）
2. **机器人自动跑分**：headless 跑 sim，断言「踢球给球速 / 球能停 / 能进球 / AI 能进 N 球 / 无 NaN」
3. **CDP 端到端**：加载 / 踢球 / 进球 / 结算 / 无报错 / 截图（计数型指标）
4. **手感量化**（M3）：触球成功率、平均控球时长、进球转化率

**红线**：验证只能证明「物理没崩、数值不失衡」，**证明不了「踢起来爽不爽」**。第一人称足球的手感最终靠清单逐项做出来，尤其是「球在脚下的可见性」和「控球距离」。

## 1. 为什么是它 —— 与现有项目的差异

game-lab 前四作：01 体素场 / 02 太阳能飞行 / 03 3D 赛车 / 04 第一人称 FPS。04 沉淀了高价值栈，但 **Rapier 在 04 里只被用来做「角色碰撞」**——它的核心能力（动态刚体、弹性、摩擦、旋转）完全没用上。

**05 让 Rapier 做它最擅长的事：把「球」当成一个真实的动态刚体。** 这是 04 栈复用度最高的一种延伸——物理引擎从「配角」变「主角」。

| 维度 | 04 FPS | 05 足球 |
|---|---|---|
| Rapier 用途 | 角色碰撞（静态用法） | **球 = 动态刚体（弹性/摩擦/旋转/Magnus）** |
| 角色模型 | 盒模型敌人（pivot 四肢） | **同技术复用** → 方块人（我的世界风） |
| 相机 | 第一人称 | 第一人称（复用） |
| AI | 战斗索敌（朝最近敌队） | **追球 / 卡位 / 射门**（多智能体协同，更贴 agent 主航道） |
| 玩法大类 | 战斗（射击） | 体育（从未覆盖） |

**为什么比我在选型时给的四个选项更好**（用户拍板后的判断）：双摇杆 Roguelike / 塔防仍是「射击大类」近亲，物理仍只是碰撞；而足球把 04 最贵的资产（Rapier + 盒模型 + KCC + 程序化音效 + sim/render + 验证体系）一次性吃满，且是 lab 从未碰过的「体育手感」+「多智能体协作 AI」两个新能力项。

**与 agent 主航道的关系**：你是 AI 专业、长期目标是 agent 项目。05 的对手 AI（追球 / 协同卡位 / 射门 / 回防）是一类**非战斗的多智能体行为**，比 04 的「朝敌人开火」更贴近「智能体如何分工协作」，是 agent 学习线的自然推进。

## 3. 玩法设计（M1 最小集，默认值待确认）

- **视角**：第一人称 PointerLock；保留「无锁拖拽」降级（headless 友好）
- **移动**：WASD + 空格跳 + Shift 疾跑（复用 KCC）
- **控球**：靠近球自动轻微吸附（带球），左键蓄力踢（力度条决定距离），球门方向默认
- **M1 内容**：1 个方块人球场 + 1 个球 + **1 名 AI 对手（追球+射门）** + 双边球门 + 进 N 球或定时结束
- **结算**：进 N 球 / 时间到 → 胜 / 负面板；一键重开

**M1 默认队伍规模 = 1v1（玩家 vs 1 AI）**，先把「控球 → 射门 → 进球 → 重开」闭环跑通；M2 扩到 3v3（玩家 + 2 AI 队友 vs 3 AI），引入协同卡位与传球。

## 5. 前瞻验证：Rapier 拟真球物理（已实测，2026-09-25）

探针：`_tmp/soccer-probe.mjs`（复用 04 的 rapier 0.20.0，Node 无头实跑；球半径 0.22m、密度 9.6→质量≈0.43kg）

| # | 项目 | 实测结果 |
|---|---|---|
| A | 弹跳（落高 1.78m） | 回弹峰 0.42m，**实测 e≈0.48**（球 0.7 ∩ 地面 0.3）✅ 不穿地、无 NaN |
| B | 抽射（初速 8.33m/s） | 10s 滚 **47m 仍未停** ⚠️ Rapier 几乎不模拟滚动阻力 |
| C | 香蕉球（绕 Y 旋 40rad/s） | 1.5s 横向偏移 **0.42m**（K=0.0009 可调）✅ 弧线可做 |
| D | 撞墙反弹 | 接近 +5.30 → 反弹 **−3.40**（比 0.64，≈平均恢复），接触 x=14.28 无穿透 ✅ |

### 探针直接得出的四条实现约束（写进代码，不要靠记忆）

1. **恢复系数默认 Average 合成**：球 0.7 ∩ 地面 0.3 → 实测 0.48。想让球「弹」，**球与地面弹性都要设高**（如球 0.8 + 地面 0.7 → 合成 ≈0.75）。
2. **必须手动加滚动阻力**：B 实测球 10s 滚 47m 不停。Rapier 不模拟滚动阻力，需每步施加 `F = -c·v`（与速度反向、与质量成比例）才能像真草皮一样停住。
3. **必须手动加 Magnus 力做弧线**：C 实测靠 `F = K·(ω × v)` 才产生横向偏移；Rapier **不原生模拟 Magnus**。K 为可调系数，香蕉球强度由它决定。
4. **撞墙反弹无穿透、合成恢复≈Average**：D 接触点精确 14.28、无隧穿，反弹比 0.64（墙 0.6 ∩ 球 0.7）。球门 / 边界同理。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| **重蹈「不好玩」覆辙**（体素沙盒模式） | §0 清单为 M1 准入条件；每个里程碑结束人工试玩对照「好玩」清单 |
| **第一人称足球操作别扭（看不到脚、球在脚下丢视野）** | **头号风险**：球加地面投影 / 高亮标记 + 相机俯角微调 + 球拖尾；M1 就把「球始终可见」列为验收项 |
| **控球手感难调（黏死 or 飞太远）** | 数值集中在 config；M3 用 bot 扫参（控球时长 / 触球成功率），人工在 2–3 组候选里裁决 |
| **球穿模 / 飞天** | 探针已证不穿墙不穿地；加线速度上限 + NaN 哨兵 + 固定步长 1/60 |
| **PointerLock 在 headless 不可用** | `window.__fps` 钩子注入输入；保留「无锁拖拽」降级 |
| **AI 抢球互相卡 / 挤成一团** | 角色间互排斥力（复用 04）；AI 与玩家共用 KCC，移动语义一致 |
| **手感调不准（太飘/太钝）** | 参数集中在 config.ts；M3 扫参 |
| **音效在无头不可听** | 只自动验证「AudioContext 节点已创建 + 无报错 + 事件计数」；听感人工验收 |
| **内容量失控** | 上限：队伍 3v3 / 1 球场 / 标准缩放；数据驱动，规模压到人工可逐条验收 |
| **headless 下 FPS 不可信** | 沿用结论：性能指标只看 draw call / 三角面数 / 实体数，不记录 FPS |
| **game-lab 无版本控制** | 开工第一件事 `git init`（05 是新仓库） |
