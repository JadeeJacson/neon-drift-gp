## 0. 先立规矩：能玩 / 好玩验收清单

**沿用 lab 制度：验收清单先于架构。** 练习期 05（第一人称足球）被删的核心教训是
「操作天然别扭的手感项目，手感没做出来就是下一个被删的」——07 用**第三人称车尾相机**
天然规避了 05 的头号风险（看不到球），但把手感风险转移到了**车感与相机**上，
所以 M1 的准入门槛必须是这两项。

### 「能玩」验收（M1 必须全过，做不完不许进 M2）

- [ ] **车能开**：油门/转向/倒车/刹车成立，不翻不飘；第三人称车尾相机跟随不眩晕
- [ ] **球物理可信**：球会弹跳/滚动/撞墙反弹/最终能停；不穿地、不穿墙、不穿车、无 NaN
- [ ] **能踢球**：车撞球有可信的动量传递 + 撞击音 + 命中反馈
- [ ] **能进球**：球过门线 → 进球判定 + 进球音 + 比分 + 重开球（kickoff）
- [ ] **有对手**：至少 1 个 AI 会追球/射门/回防；玩家能抢断也能被进球
- [ ] **有胜负**：定时或进 N 球结束 → 结算面板；一键重开

### 「好玩」验收（M2–M3 目标）

- [ ] **车感成立**：漂移/急转跟手，boost 提供速度快感；车不是「滑冰」也不是「卡车」
- [ ] **相机可用**：球追随模式（ball-cam）与车追随模式可一键切换，高速时视野不丢球
- [ ] **对抗张力**：kickoff 抢球、门前混战、回追解围这些经典时刻能自然发生
- [ ] **AI 可读**：追球/带球/射门/回防/守门分工清楚，不是木头
- [ ] 单局 **3–5 分钟**，丢球后 **< 3 秒**重开（低挫败、高重试）

## 2. 核心机制清单（第一版）

### 2.1 车（手感之源，最高优先级）

- 街机车：油门/转向/刹车倒车 + **手刹漂移**（M1 就要，车感核心）+ 跳跃/二段跳翻滚冲刺（M2）
- 实现走 **VehicleBody3D**（raycast 车轮）；车身碰撞体用盒近似（GLB 车模挂子节点）
- 模型：Kenney Car Kit 的 kart-\* 系（5 色）与 race-future / sedan-sports 备选

### 2.2 球

- RigidBody3D + 物理材质弹跳；球半径按场景比例定（车长约 4 m 的工作台面）
- 弧线球（Magnus）M2：手动 `F = K·(ω × v)`

### 2.3 球场与规则

- 1 张围墙球场（围墙反弹 = 乐点之一），两端球门；夜景灯光 + 看台/城市剪影氛围
- 规则状态机：`KICKOFF → PLAYING → GOAL(庆祝+回放位) → KICKOFF → … → FULL_TIME(结算)`
- 进 N 球或定时结束；进球后 < 3 s 重开；比分/计时 HUD

### 2.4 AI（多智能体，贴合用户 agent 主航道）

- 1v1 起步（M1）：对手 AI = 追球 → 带向对方球门 → 射门 → 丢球后回防
- 2v2（M2）：队友/对手分工（进攻/补位/守门），角色分配用简单打分（距球距离+朝向）
- 决策做成 sim 纯函数（输入：球/车状态快照 → 输出：意图），场景层只执行——沿用 06 分工线

### 2.5 物理实现约束（05 探针教训平移，M1 首日做 Godot 版探针实测）

1. **弹跳恢复系数合成规则先实测**（Godot 4 物理材质 bounce 的合成方式与 Rapier 不一定相同），
   想让球「弹」起来，球与地面的 bounce 取值都要探针确认；
2. **滚动阻力要手动补**：Rapier 实测 10 s 滚 47 m 不停；Godot 用 `linear_damp`/`angular_damp`
   起步，不够就手动 `F = -c·v`，目标「球 5–8 s 内自然停住」；
3. **Magnus 不原生支持**，手动加力，K 为可调系数；
4. **高速球穿隧**：开 continuous collision detection + 线速度上限；
5. **物理不确定性**：Godot Physics 不保证逐帧复现（路线图 §4.3 已接受），所有平衡结论走
   统计断言（多种子跑分看区间），逐帧可比的逻辑（规则状态机/比分/AI 决策）下沉 sim。

## 4. 难度平衡与 AI 跑分（方法论平移）

- **三画像**：守门流（保守，堵门少出击）/ 普通（攻守均衡）/ 高手流（激进压迫+精准射门）。
  要的形状：**守门流险胜 AI 或小负、普通五五开、高手稳定胜**——区间断言锁进
  `sim/tests/test_match_sim.gd`（沿用 06 的「难度不是单调旋钮，中段最易塌」教训，调参时盯中段）。
- **跑分指标**：射门转化率、场均失球、kickoff 胜率、boost 净收益、整局时长。
- **AI 难度旋钮**：反应延迟（感知快照间隔）、射门精度噪声、回防积极性——三档画像即三个参数组。
- **知识资产**（记录链接，AI 提炼成参数表）：Rocket League kickoff 时机拆解、
  RLBot 决策分层文、GDC 相机设计演讲（ball-cam 的取舍）。

## 7. 风险与应对

| 风险 | 应对 |
|---|---|
| **车感调教失败**（头号风险：VehicleBody3D 参数敏感，可能「滑冰」或「开船」） | M1 首日物理探针实测参数敏感性；数值全部集中 config；参数扫描 + 人验点前移（不等 M3） |
| **相机丢球/眩晕** | M1 就做双相机模式 + 一键切换；球永远可见列为验收项（05 教训） |
| **高速球穿隧** | CCD + 线速度上限 + 进球判定用门线传感器而不是位置比较 |
| **AI 挤车/卡墙**（05 教训） | 车车互斥推力 + 卡墙检测回中；AI 与玩家共用同一套车辆控制接口 |
| **物理不确定** | 接受（路线图 §4.3）；结论走统计断言，逐帧逻辑下沉 sim |
| **「好玩」押在对抗手感上** | §0 清单为 M1 准入；每里程碑人工试玩对照「好玩」清单 |
| **内容量失控** | 上限：1 球场 / 1v1→2v2 / 车型 2–3 种 / 无道具无自定义；数据驱动 |
| **headless 下 FPS 不可信** | 沿用结论：性能只看 draw call/面数/实体数 |

## 10. 启动方式与键位

```bash
engines/godot/4.7.2/Godot_v4.7.2-stable_win64.exe --path projects/07-car-soccer
```

`WASD` 油门/转向 · `S` 刹车/倒车 · `Space` 跳跃（空中再按=翻滚冲刺）· `Shift` boost ·
`Ctrl` 手刹漂移 · `鼠标右键` 切换球追随/车追随相机 · `Esc` 释放鼠标 · `Enter`（终场）重开。

制作人按序打分：① 油门/漂移跟手度 ② ball-cam 是否眩晕 ③ 车速/boost 力度 ④ 撞球与进球反馈 ⑤ HUD 可读性。
回报方式：「第 N 项，具体描述」，AI 改数值或场景并重跑验证。
