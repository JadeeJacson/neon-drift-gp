# 三项目横向对比：04-合并版 vs 04_1 vs cf-transport-ship（运输船）

> 对比对象：
> 1. **04-web-fps-arena**（合并升级版，TS + three.js r186 + Rapier，sim/render 分离）
> 2. **04_1_frontline-cq**（TS + vite，程序化音频与射击手感见长）
> 3. **cf-transport-ship**（运输船，three.js r149 UMD 免构建，单全局命名空间）
>
> 主人已给的判断：04_1 的**换弹、枪械音效**不错；运输船的**第一人称枪械和手的建模、地图、人物模型**不错。以下从代码层面逐项验证这三条判断，并补齐其余维度。

---

## 一、逐项验证主人的三条判断

### 1. 04_1 的换弹 —— 属实，但机制本身偏简单，好在「反馈链」完整

`src/entities/Player.ts`（189–193 行）：`reloadTimer` 倒计时结束后 `ammo = WEAPON.magSize`。机制本身是标准的「定时器换弹」，并不复杂。

真正让它手感好的是配套反馈链：
- `AudioSystem.reload()`：两段式 click（620Hz → 120ms 后 430Hz），模拟退匣+上膛两声；
- HUD 有换弹进度提示（`Hud.ts`）；
- 输入层在换弹中屏蔽开火（`InputController.ts`）。

**结论**：换弹的「机制」三家大同小异（04 合并版也有 R 键换弹+定时器），04_1 赢在**音效分层 + UI 反馈**，这是可以直接平移的部分。

### 2. 04_1 的枪械音效 —— 属实，且有两处它独到的设计

`src/systems/AudioSystem.ts`：
- 枪声 = 爆裂噪声（bandpass 1500Hz，Q0.7，0.14s 指数衰减）+ 低频三角波冲击（180→48Hz），**pitch 由种子 RNG 做 ±6% 抖动**——每枪音色微不同，避免机关枪式的机械重复感。这是它比 04 合并版（单一 gunShot、无抖动）和运输船（按枪型分音色但节奏固定）都细的地方；
- `distantShot()`：远处的枪用 lowpass 420Hz 低通闷响区分，战场空间感好；
- 全局 duck（音量闪避）、噪声缓冲复用（1.2s buffer 反复 start/stop，零分配）。

**对照运输船** `src/core/audio.js`（229 行）：音色更精致（`shot_ak` = bandpass 2400→420 扫频 + highpass 5200 + 三角波 150→46），且有**金属船体混响**（双 delay 0.043/0.081 反馈环）和空间音频。单论单发音质运输船更好，但 04_1 的 pitch 抖动 + 远/近分层设计思路值得保留。

### 3. 运输船的第一人称枪械/手建模 —— 属实，明显是三家最强

`src/weapons/viewmodel.js`（340 行）：
- **7 把程序化枪模**（ak/m4/awm/mp5/deagle/knife/grenade），每把有独立的 muzzle/eject 挂点（供枪口焰和弹壳抛射用）；
- `addArms()`：双手手套 + 袖管，握持姿态按枪型调整；
- **双通道 vmScene + vmCamera 叠加渲染**——枪模永远不穿墙，这是 04 合并版已经移植的做法（源头即此处）；
- 换弹动画不是简单的整枪下移：dip 下沉 + 抖动 + **拉栓动作**（`reloadT < 0.32` 时枪身 rx 偏转），加上抽枪动画、冲刺倾斜、**每枪独立的 ADS 位置**、呼吸 sway。

**对照 04 合并版**：viewmodel 是单把枪 + 双臂，换弹只有音效+进度条，没有枪身动画。**这是 04 家目前最大的一块短板，运输船这套代码是理想的移植源。**

### 4. 运输船的地图 —— 属实

`src/world/map.js`（524 行）：运输船甲板主题，有真正的**垂直设计**——板条箱塔 + 楼梯可上集装箱「二楼」、V 形集装箱阵、L 形堆叠、**单向管道（one-way pipes）**做单向捷径。出生点有房子掩护，海面环境。配套 `buildNav()` 从可站立表面采样生成 navmesh（含跳跃边），还有 `selfCheck()` 自检几何穿模。

**对照**：04 合并版的 `yard` 工地图是纯平面 + 方块掩体（无二层、无单向通路）；04_1 地图同样以平面掩体为主。运输船的地图设计理念（垂直层级 + 单向回路）是三者中唯一的。

### 5. 运输船的人物模型 —— 属实

`src/entities/character.js`（242 行）：髋部根骨骼（hips→torso→head/arms + 双腿），带背心、弹匣包、**带檐头盔**、分队头饰（头巾/风镜）、面罩，**手中持有枪模**、蹲伏姿势（身高比 0.66）、死亡动画、受击闪白、头顶名字 Sprite。

**对照 04 合并版**：方块人 + 头盔半球 + 马甲 + 枪模（已从 04_1/04_2 借鉴），但无骨骼、无蹲伏、无死亡动画。运输船的人形明显更完整。

## 二、其余维度对比

### AI

| | 04 合并版 | 04_1 | 运输船 |
|---|---|---|---|
| 架构 | 自写行为树（Selector/Sequence）+ 掩体点采样 + 反应延迟 | 隐式意图向量 FSM（+攻/防角色） | 显式 3 态 FSM + 爆发射击 |
| 寻路 | **无**（直线移动 + LOS 绕行） | **无** | **nav-grid BFS 寻路**，0.6s 重规划，卡死兜底 |
| 特色 | 掩体Seek、受压判定、模式门控（保护生存基线） | 意图向量平滑，走位自然 | 沿真实 navmesh 绕障碍追人 |

**AI 最强：运输船**（唯一会绕路追人的）。04 合并版的行为树工程化更好（确定性、零分配、可被 bot 基线覆盖测试），但不会寻路，遇到复杂地形会卡。两者结合是理想态。

### 物理 / 枪械数据

- **运输船**：自写 OBB 碰撞世界（broad-phase 网格 + 射线 + 单向阀），27/27 单测；武器定义最全（AK/M4/AWM/MP5/Deagle，伤害/射速/爆头倍率/护甲减伤/后坐力 pattern 全套）。
- **04 合并版**：Rapier 物理引擎（KCC 角色控制器、TOI 射线），物理正确性最高，但武器种类少、无后坐力 pattern。
- **04_1**：轻量自写碰撞，居中。

### 工程化 / 可验证性（04 合并版压倒性领先）

| | 04 合并版 | 04_1 | 运输船 |
|---|---|---|---|
| 语言/构建 | TS + vite + tsc 严格检查 | TS + vite | **纯 JS 全局命名空间，免构建**（file:// 直开） |
| sim/render 分离 | ✅ sim 层零 three.js，Node 可跑 bot 基线 | ❌ 混合 | ❌ 混合 |
| 确定性 | 种子 RNG + 固定步长 | 部分 | ❌ |
| 自动化验证 | CDP 18 断言 + bot 计分基线 | 少量 | physics 27/27 + selfCheck |
| three.js 版本 | r186（最新） | 较新 | **r149（旧，2022 年）** |

运输船的免构建是有意为之的便携设计，但代价是没有类型检查、没有模块边界、渲染与逻辑耦合，后续迭代成本最高。

### 画面渲染

- 04 合并版：ACES tone mapping + PCFSoft 阴影 + UnrealBloom + MSAA×4，最「现代」；
- 04_1：绘制调用约 100，光照氛围好；
- 运输船：r149 基础管线，靠模型细节取胜，无后期。

---

## 三、总结与移植建议

**一句话**：04 合并版赢在**架构与工程化**，运输船赢在**内容资产（枪模/人形/地图/单发音质/AI 寻路）**，04_1 赢在**手感反馈细节（音效分层、换弹链路）**。三者恰好互补。

若下一步做整合（以 04 合并版为底座），优先级建议：

| 优先级 | 移植项 | 来源 | 理由 |
|---|---|---|---|
| P0 | viewmodel 7 枪模 + 双手 + 换弹/抽枪动画 | 运输船 viewmodel.js | 补最大短板，主人点名认可 |
| P0 | 髋骨骼人物模型（蹲伏/死亡动画） | 运输船 character.js | 替换方块人，主人点名认可 |
| P1 | 换弹双段音 + pitch 抖动 + 远/近枪声分层 | 04_1 AudioSystem | 主人点名认可，代码即插即用 |
| P1 | 金属混响 + 空间音频 | 运输船 audio.js | 叠加在 04_1 思路上 |
| P2 | 运输船式垂直地图（二层 + 单向通路） | 运输船 map.js | 需重写为 04 的 sim/arena 结构，工作量大 |
| P2 | nav-grid BFS 寻路接入行为树 | 运输船 bots.js | 让 AI 真正会绕掩体，需适配 sim 层 |

风险提示：运输船代码是纯 JS + r149 + 全局命名空间，移植需要改写为 TS 模块并适配 sim/render 分离架构，不是复制粘贴；预计 P0 两项各需一次完整会话，P2 的地图与寻路合在一起才算完整收益。
