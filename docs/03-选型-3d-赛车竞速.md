## 0. 先立规矩：能玩 / 好玩验收清单

**沿用 05 的制度：验收清单先于架构。** 上一任 05（体素沙盒）技术全绿却被删，原因是不好玩。

### 「能玩」验收（M1 必须全过，做不完不许进 M2）
- [ ] 车有**真实载具手感**：油门/刹车/转向有惯性、会打滑、悬挂会压缩，不是"贴地平移的盒子"
- [ ] **相机跟随平滑**：车后上方跟随，不穿地、不抖动、转弯时不甩飞
- [ ] 一条赛道能**完整跑完**：起点 → N 个检查点 → 终点，圈数与计时正确
- [ ] 键盘全覆盖：W/↑ 油门、S/↓ 刹车倒车、A/D/←/→ 转向、空格手刹、R 重置、C 切视角
- [ ] **即时反馈**：速度 HUD、当前圈/总圈、计时、漂移火花、引擎音（WebAudio 合成）

### 「好玩」验收（M2–M3 目标）
- [ ] **5 条赛道各有性格**（宽窄、弯道类型、路面摩擦、高低差各不相同）
- [ ] **AI 对手让比赛成立**：至少 1 个对手，名次实时变化，不是单机跑圈
- [ ] 存在**走线技巧**：切弯心（APEX）能显著缩短圈速——计时提供客观判据
- [ ] 单圈 **40–90 秒**，撞墙/掉出赛道后 **< 2 秒**回到赛道（低挫败、高重试）

### 验证四轨
1. **物理确定性回放**（M1 起）：同输入序列步进 N 次，位置与朝向哈希一致
2. **机器人自动跑圈**（M2 起）：headless Rapier 直接跑赛道，断言"5 条赛道都能跑完"并留档圈速
3. **CDP 端到端**（M1 起）：加载 / 切赛道 / 碰撞 / 检查点 / 计时 / 无报错 / 截图
4. **手感量化**（M3）：极速、0–100 加速时间、过弯速度损失、圈速分布

**红线**：验证只能证明「物理没崩、赛道能跑完」，**证明不了「开起来爽不爽」**。
手感最终要靠清单逐项做出来，不靠测试通过——M3 的自动扫参只能缩小人工裁决的搜索空间。

## 1. 为什么是赛车竞速

### 1.1 与已有项目完全岔开

| 项目 | 形态 | 空间 | 重心 |
|---|---|---|---|
| 01 熵流 | 弹幕射击 | 2D 正交 | 技巧（躲避） |
| 02 极向 | 精准平台跳跃 | 2D 正交 | 技巧（手感） |
| 03 回路 | 塔防 | 2D 正交 | 策略 |
| 04 等距 RPG | 探索 + 战斗 | 2.5D 等距（正交相机） | 叙事 + 内容 |
| 05 卡牌构建 | Roguelike 卡组 | 无空间（DOM） | 策略 |
| **03 弯心** | **赛车竞速** | **真 3D（透视相机）** | **技巧（载具物理）** |

路线图 §1 明确写着**未覆盖：真 3D**。赛车是 C 组里唯一同时满足
「物理即玩法」+「有对手即对局成立」+「零资产可做」（程序化几何路面 + 盒子车模）的形态。

### 1.2 物理引擎是路线图点名的引入点

路线图 §4.1 物理层原文：

> 物理引擎（Rapier / Matter）—— **待首个真需要物理的形态（物理沙盒 / 3D 平台）再引入**

本形态把物理从"辅助碰撞"提升为**玩法核心**。且 Rapier 自带
`DynamicRayCastVehicleController`（射线投射车轮 + 悬挂 + 引擎力/转向/刹车），
比手写车辆动力学稳定得多——**手感基线由引擎物理给出，不必从零调动力学曲线**。

### 1.3 可玩性风险可控（回应 05 的教训）

05 被删的根因是"堆工程化而漏掉手感与反馈"。赛车形态结构上迫使手感优先：
车加速、打滑、撞墙、飞跃——**这些反馈在第一天就有**。
且"快"本身就是强反馈（速度感 = FOV 变化 + 拖尾 + 引擎声），不需要等系统搭完。

## 2. 技术栈

| 组件 | 版本 | 依据 |
|---|---|---|
| **three.js** | **0.186.0** | registry 实测（04 在用）；`@types/three` 0.186.0 必须对齐 |
| **@dimforge/rapier3d-compat** | **0.20.0** | registry 实测；`-compat` 变体内联 WASM，浏览器与 Node 通用 |
| TypeScript | 7.0.2 | 沿用 |
| Vite | 8.3.0 | 沿用，dev 端口 **5179**（避开 5178） |
| 音效 | WebAudio 合成（M3） | 沿用 01 / 03 模式 |

### 为什么**不换**渲染库（控制变量原则）

路线图 §0.2：**每个项目只引入 1–2 个新维度**。本次新变量已经有两个：

- **空间**（2.5D 正交 → 真 3D 透视相机）
- **物理**（自研 AABB → Rapier WASM 载具物理）

若同时把 three.js 换成 Babylon.js（registry 实测 9.27.1）或 Godot，新变量变成 3–4 个，
失败将无法归因（路线图原话："违反它，失败就无法归因"）。
**Godot 留给候选 10**（需下载引擎 + 无头验证覆盖率必然损失 = 那是它的课题）。

### 分层架构（沿用 sim/render 分离，已验证有效）

```
src/
├─ core/config.ts     车辆参数 / 赛道参数 / 相机参数 —— 自动扫参只动这里
├─ sim/               ★ 零 three、零 DOM：Rapier 世界 + 赛道 + 比赛规则
│  ├─ vehicle.ts      车辆控制器封装（引擎力 / 转向 / 刹车 / 手刹）
│  ├─ track.ts        5 条赛道数据（控制点 → 中心线 → 路面段 + 检查点）
│  ├─ drive.ts        驾驶输入（玩家 / AI / 回放统一接口）
│  ├─ ai.ts           AI 对手：前瞻点追踪 + PD 转向
│  └─ race.ts         比赛状态机：检查点 / 圈数 / 计时 / 名次 / 重置
├─ render/
│  ├─ scene.ts        three.js 场景：路面 ribbon、护栏、天空、光照
│  ├─ car.ts          程序化车模（盒子车身 + 4 轮）+ 轮胎拖痕
│  ├─ camera.ts       第三人称跟随相机（速度相关 FOV）
│  └─ hud.ts          速度 / 圈数 / 计时 / 名次 / 小地图
└─ main.ts            组装 + window.__racer 验证接口
```

sim 层只依赖 Rapier，**不依赖浏览器**——这是"机器人自动跑圈"能跑在 Node 里的前提。

## 3. 玩法（M1 最小集）

- **操作**：W/↑ 油门、S/↓ 刹车倒车、A/D/←/→ 转向、空格手刹（锁后轮 → 漂移）、R 重置、C 切视角
- **目标**：绕赛道跑 **3 圈**，与 1 个 AI 对手竞速，按总时间排名
- **M1 赛道**：1 条（宽阔椭圆 + 两个弯），路面用分段 cuboid 碰撞体（比 trimesh 稳定）
- **相机**：第三人称跟随（车后 7m、上方 3m），速度越快 FOV 越大、距离越远

**M3 的"手感自动扫参"是本项目的方法论突破点**：02 号项目档案记着"调校敏感：依赖人类感觉回路，AI 无内在感受"。
本项目把手感转成**可测数字**（0–100 加速、极速、过弯速度损失、圈速），
用机器人跑分为目标函数，在 config.ts 上做小规模参数扫描——
**第一次让"手感"进入可自动验证的范围**（不替代人工试驾，但把搜索空间缩到人工可裁决的量级）。

## 5. 前瞻验证：Rapier 载具无头确定性（已实测）

在 `_tmp/rapier-probe/probe-vehicle.mjs` 用 `DynamicRayCastVehicleController` 跑了固定输入序列：

| 项 | 实测结果 |
|---|---|
| Node 无头构建车辆控制器 | ✅ 成功（4 轮射线悬挂） |
| **确定性** | ✅ 三次相同输入，末态位置与四元数**完全一致**（`158.277405,1.469975,-149.343033` ×3） |
| 加速性能 | 0→25 m/s（90 km/h）约 5 秒，转向弧线正常 |
| 单步耗时 | 0.008 ms（900 步 7.2 ms）——可支撑上万次仿真 |

**结论**：`物理确定性回放` 与 `机器人自动跑圈` 两个新验证模式均可行，
且顺带为路线图候选 11（异步对战 + 确定性回放）预热了确定性基础设施。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| **车辆物理调不准**（太飘 / 太钝 / 翻车） | 参数集中在 config.ts；M3 用机器人跑分扫参，把人工裁决范围缩到 2–3 组候选。底盘重心下移（质心偏移）防翻车 |
| **路面碰撞用 trimesh 卡轮** | 改用**分段 cuboid** 路面碰撞体（沿中心线每段一个盒子），视觉用连续 ribbon mesh——物理稳定优先 |
| **相机穿地 / 甩飞** | 相机目标高度与最小离地限制；位置弹簧插值；速度越快插值越硬 |
| **掉出赛道挫败** | 掉出后 1.5 秒内自动重置到最近检查点（保留当前圈计时，惩罚最小化） |
| **赛道内容量**（02 曾在此崩塌） | 只做 5 条，数据驱动（控制点数组 → 程序化几何），规模压到"人工可逐条验收" |
| **headless 下 FPS 不可信**（05 结论） | 性能指标只看 draw call / 三角面数，不记录 FPS |
| **AI 对手太强/太弱** | AI 用与玩家相同的车辆物理（公平），强度靠"目标速度系数"单一参数调节 |
