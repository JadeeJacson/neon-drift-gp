# 16 · LUMEN BENCH 光域实验场 —— TA 渲染上限测试（立项与结论）

> 日期：2026-09-28 起，2026-09-29 完成第一轮。
> 工程：`projects/16-lumen-bench/`；**技术参数与实测细节全在工程内 `README.md`**，本文只记定位、决策与结论。

## 1. 为什么要做这个

路线图 §0.2 要求「素材优先、禁止从零造资产」，正式期六个项目都按这条走。
但一直没回答过一个基础问题：**Godot 4.7 的美术上限到底在哪，上限由什么决定？**
素材库路线回答不了它——因为素材质量会盖过引擎能力的信号。

制作人指令明确：**不复用任何既有素材**，做一个高标准测试场景，
评估三条轴：美术风格表现力 / 场景搭建复杂度 / 灯光渲染上限。
所以本工程是 §0.2 的**有意例外**（受控变量：全部产物由代码生成，
才能把"引擎能给什么"单独量出来），**不构成新项目的先例**。

## 3. 结论摘要（详见工程 README §3–§5）

1. **复杂度可行**：436k 静态三角面、202 节点、132 根栏杆柱 + 240 块碎石走 MultiMesh，
   18 盏灯（阴影配额 3），装配 11.6 s。程序化路线的胜负手是
   **世界三向投影（world triplanar）+ 参数曲面**：免展 UV、无接缝，"零素材"才可施工。
2. **灯光上限**：SDFGI 在封闭穹顶空间是决定性的（关掉后厅内 6.6% 死黑、无彩色反弹）；
   体积雾 + 前向散射 + 浮尘让低角度日光成为实体；`Light3D.light_projector` 能做出真正的彩窗 gobo 投影。
3. **性能档位**（1920×1080 / RTX 4060 Laptop / Vulkan / Forward+）：
   direct 165.6 → base 101.9 → cine 74.0 → ultra 59.5 fps。
   **`direct→base` 是质变，`cine→ultra` 是花拳**（-24% 帧率换 0.3→0.0 暗部占比）。
4. **没打通的两处上限**（诚实记录）：
   - 2D 平铺 LUT：4.7 的 `adjustment_color_correction` 收 Texture2D，
     但 identity 图在 4×4/256² 与 8×8/512² 版式下都**不是恒等映射** → 分级只能靠 `adjustment_*` + 自定义后期 pass。
   - 物理相机（`CameraAttributesPhysical`）**没有景深属性**，真实曝光三要素与 DOF 二选一。
5. **下一步该测的轴**：SDFGI 打底 + `LightmapGI` 补近景（薄结构与藻井深缝的 AO/反弹仍不如烘焙干净）、
   `CompositorEffect` 自定义 HDR 后期、`OccluderInstance3D` 遮挡剔除。

## 4. 沉淀到路线图的教训（已写入工程 README §4，共 25 条）

其中会反复咬人的四条：

- **4.7 着色器矩阵内置改名**：`CAMERA_MATRIX→INV_VIEW_MATRIX`、`INV_CAMERA_MATRIX→VIEW_MATRIX`，
  且 **fragment 阶段没有世界坐标内置**（`world_vertex` 等在 4.7 不存在），世界坐标要在 `vertex()` 里取好用 varying 传。
- **`TorusMesh` 改名且改语义**：`outer_radius = R + r`、`inner_radius = R − r`。
  按旧 `major/minor` 习惯传 (R, r) 会得到"胖甜甜圈"——本工程画面里那颗黑球就是它。
- **`flip` 必须同时翻转顶点绕序**：只翻转法线属性时，背面剔除仍按原绕序判定，
  结果是"法线朝厅内、正面朝厅外"，整面墙在厅内直接消失。这是本工程最贵的一次调试。
- **`WorldSettings` 类没了**（换成 `World3D` 资源）；SDFGI 的注入细节项目设置被大幅自动化删除，可调面变窄。
