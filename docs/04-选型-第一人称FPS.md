## 0. 先立规矩：能玩 / 好玩验收清单

**沿用 05 / 03 两任项目验证过的制度：验收清单先于架构。**  
前两任被删的项目（体素沙盒、上一版 04 波次射击）都是「技术全绿但不好玩」。

### 「能玩」验收（M1 必须全过，做不完不许进 M2）

- [ ] **第一人称视角成立**：鼠标转视角（PointerLock），WASD 移动，有重力与落地，不穿墙、不卡墙角
- [ ] **开枪有反馈**：枪口火光 + 后坐力（视角上跳 + 回落）+ 弹壳/弹道曳光 + **开火音**
- [ ] **命中可感知**：命中敌人有 hitmarker + 敌人受击顿帧/染色 + **命中音**；击杀有倒地/碎裂 + **击杀音**
- [ ] **一种武器打完整循环**：开火 → 弹药减少 → 打空 → 换弹（有换弹动作与音）→ 恢复射击
- [ ] **敌人会威胁你**：至少 1 种敌人会接近并开火，玩家会掉血，掉血有屏幕反馈（红边/震动）
- [ ] **有胜负**：HP 归零 → 失败结算；清完最终波 → 胜利结算；都能一键重开

### 「好玩」验收（M2–M3 目标）

- [ ] **3 把武器手感互不相同**（手枪精准单发 / 步枪连发压枪 / 霰弹近战多弹丸），切换有意义
- [ ] **敌人有可读的行为模式**：接近、侧移绕圈、开火前有预警，不是站着挨打的靶子
- [ ] **波次节奏成立**：5 波难度递增，每波之间有喘息，最后一波有精英/Boss 感
- [ ] **存在技巧空间**：爆头（命中上半部）伤害更高、走位躲弹、换弹时机管理
- [ ] 单局 **3–6 分钟**，死亡后 **< 2 秒**可重开（低挫败、高重试）

### 验证四轨

1. **确定性回放**（M1 起）：同输入序列步进 N 次，玩家与敌人末态一致 —— **探针已实测成立**
2. **机器人自动跑分**（M2 起）：headless 跑 sim，断言命中率 / TTK / 波次可通 / 平衡区间
3. **CDP 端到端**（M1 起）：加载 / 开火 / 命中 / 换弹 / 受伤 / 结算 / 无报错 / 截图
4. **手感量化**（M3）：TTK、DPS、散布半径、后坐力回落时间、每波存活率

**红线**：验证只能证明「物理没崩、数值不失衡」，**证明不了「打起来爽不爽」**。  
射击手感最终靠清单逐项做出来；M3 的自动扫参只能把人工裁决的搜索空间缩到 2–3 组候选。

## 1. 为什么又是 FPS —— 与已删的那一版 04 有什么不同

**这是本次立项必须先回答的问题。** `README §7` 与路线图都记着：上一版 04（3D 波次射击 FPS）  
已完成 sim 层与验证体系后被删除。重做同形态，如果做法不变，结果大概率也不变。

### 1.1 上一版被删的根因（推断，需正视）

上一版留下的记录里，**sim 层与验证体系是齐的**，缺的是「好玩」那一栏的证据：  
命中反馈、武器手感、音效、敌人威胁感——这些在文档里没有对应的验收条目。  
它符合了 DoD 的第 1、2 条（typecheck / CDP），倒在第 3、4 条（人眼验收 / 反馈与氛围）。

> 这与 05 体素沙盒被删是同一个失败模式：**工程化先行，手感与反馈后置，后置的部分最后没做。**

### 1.2 这一版的四点做法差异

| 维度   | 上一版 04        | 这一版 04                                      |
| ---- | ------------- | ------------------------------------------- |
| 验收顺序 | 先 sim 与验证体系   | **手感与反馈写进 M1 准入条件**（§0 清单，没过不许进 M2）         |
| 音效   | 未列            | **列为 DoD 硬指标**（本次用户拍板），M1 就要有开火/命中/击杀/换弹四种音 |
| 敌人   | （无记录）         | 敌人 AI 与威胁感进 M1 「能玩」清单，无威胁的靶子不算游戏            |
| 里程碑  | 一次性铺 sim + 验证 | **新变量分里程碑引入**（§4），每个里程碑只背 2–3 个新变量          |

### 1.3 为什么仍然值得做

- 路线图 §2 把「第一人称 FPS 战斗」列为 ★★★ 首选，理由成立：复用 03 的工程骨架与 Rapier 程度最高。
- 参考标尺（riba2534/claude-opus-5-5-demo）里三个 demo 之一即为 FPS 形态，  
  而 lab 至今三个项目（体素 / 太空 / 赛车）**没有任何一个覆盖「战斗」这个玩法大类**。
- 「射击手感」是 lab 尚未碰过的一类手感（03 是载具手感，02 是跳跃手感），属于未覆盖的能力项。

## 2. 技术栈

| 组件                            | 版本                 | 依据                                       |
| ----------------------------- | ------------------ | ---------------------------------------- |
| **three.js**                  | **0.186.0**        | 路线图 §3 基线；`@types/three` 0.186.0 必须对齐    |
| **@dimforge/rapier3d-compat** | **0.20.0**         | 03 在用；`-compat` 变体内联 WASM，浏览器与 Node 通用   |
| TypeScript                    | 7.0.2              | 严格模式（含 `noUncheckedIndexedAccess`）       |
| Vite                          | 8.3.0              | dev 端口 **5181**（03 占 5179，顺延；strictPort） |
| 音效                            | **WebAudio 程序化合成** | 零资产；03 已有 `src/audio/engine.ts` 可作架构参考   |

**不换渲染库**（控制变量原则，路线图 §0.2 / §3）：本次新变量已经足够多，再加 Babylon 或 Godot 会让失败无法归因。

### ⚠️ 新变量偏多，必须分层（对控制变量原则的正面回应）

路线图 §0.2 要求「每个项目只引入 1–2 个新维度」。FPS 实际有 5 个：  
第一人称相机 / 射线命中 / 敌人 AI / 武器手感 / 音效。  
**处理方式：按里程碑分层，每个里程碑只背 2–3 个**（见 §4）。  
这是本次立项最主要的结构性风险，序列化地引入是唯一可行的缓解手段。

### 分层架构（沿用 sim/render 分离）

```
src/
├─ core/config.ts     玩家/武器/敌人/波次/相机/音频参数 —— 自动扫参只动这里
├─ sim/               ★ 零 three、零 DOM：Rapier 世界 + 规则（Node 可跑 bot）
│  ├─ player.ts       角色控制器（KCC 封装：重力/落地/贴地/滑移）
│  ├─ weapons.ts      武器状态机（射速/弹匣/换弹/散布/后坐力曲线）
│  ├─ shooting.ts     射线命中判定 + 伤害 + 命中部位（爆头）
│  ├─ enemy.ts        敌人 AI（接近/侧移/开火预警/受击/死亡）
│  ├─ waves.ts        波次与胜负状态机
│  └─ world.ts        竞技场几何 + 掩体生成
├─ render/
│  ├─ scene.ts        场景/光照/天空/雾
│  ├─ arena.ts        程序化竞技场（地面/掩体/边界）
│  ├─ viewmodel.ts    手中武器模型 + 枪口火光 + 后坐力位移
│  ├─ fx.ts           曳光/命中火花/血液/碎裂粒子/屏幕震动
│  └─ camera.ts       第一人称相机（yaw/pitch + 后坐力偏移 + 震动）
├─ audio/synth.ts     WebAudio：开火/命中/击杀/换弹/受击/波次
├─ ui/hud.ts          HP/弹药/波次/准星/hitmarker/结算面板
└─ main.ts            组装 + window.__fps 验证接口
```

sim 只依赖 Rapier，不依赖浏览器 —— 这是 bot 跑分能跑在 Node 里的前提（03 已验证该分层有效）。

## 3. 玩法设计（M1 最小集）

- **视角**：PointerLock 鼠标转视角；**同时提供「无锁拖拽模式」**（既是 headless 降级路径，也是可访问性选项）
- **移动**：WASD 移动 + 空格跳跃 + Shift 疾跑；有重力、落地、撞墙滑移
- **射击**：左键开火（步枪连发）、R 换弹；射线命中，命中上半部为爆头（伤害 ×2）
- **M1 敌人**：1 种（追踪型），会接近到射程内并周期性开火，玩家会掉血
- **M1 内容**：1 个竞技场 + 1 把步枪 + 1 种敌人 + 3 波（第 3 波为结算波）
- **结算**：清完波次 → 胜利（用时/命中率/爆头数）；HP 归零 → 失败；均可 R 重开

M2 扩到 3 武器 × 3 敌人 × 5 波，全部数据驱动（config 数组）。

## 5. 前瞻验证：Rapier 第一人称 + 射线射击（已实测，2026-09-24）

探针：`_tmp/fps-probe/probe.mjs`（复用 03 的 rapier 0.20.0，Node 无头实跑）

| #  | 项目        | 实测结果                                                 |
| -- | --------- | ---------------------------------------------------- |
| A1 | 静止落地      | `y=0.8601`，grounded=true（胶囊半高 0.5 + 半径 0.35 = 0.85）✅ |
| A2 | 撞墙        | 前进 180 步停在 `z=5.39`（墙面 5.75 − 半径 0.35）✅ 不穿墙          |
| A3 | 斜撞墙滑移     | `Δx=10.14, Δz=0.0000` ✅ 沿墙滑移，不卡死                     |
| B0 | **不排除自身** | `t=0.000` —— **复现「打中自己」**：眼高 1.6 在胶囊内部（顶 1.71）       |
| B1 | 遮挡        | 墙后敌人 → 命中 `wall t=5.750` ✅ 遮挡剔除正确                    |
| B2 | 命中敌人      | 无遮挡敌人 → 命中 `enemy2 t=4.633` ✅                        |
| B3 | 背向射击      | `null` ✅                                             |
| C  | 确定性       | 600 步两次末态逐位一致 `10.503654,0.859946,5.389822` ✅        |
| D  | 性能        | 600 步 11.5ms，单步 **0.019ms** ✅ 可支撑上万次仿真               |

### 探针直接得出的两条实现约束（写进代码，不要靠记忆）

1. **射击必须排除自身碰撞体**：`world.castRay(ray, maxToi, true, undefined, undefined, playerCollider, playerBody)`。  
   不排除则每发子弹都在 `t=0` 命中自己。
2. **Rapier 0.20 的命中距离字段名是 `timeOfImpact`，不是 `toi`**（`toi` 是 0.11 时代的旧名，网上教程大量沿用）。  
   类型定义：`dist/geometry/ray.d.ts` 的 `RayColliderHit`。

## 6. 风险与应对

| 风险                             | 应对                                                               |
| ------------------------------ | ---------------------------------------------------------------- |
| **重蹈上一版 04 的覆辙**（技术全绿但不好玩）     | §0 清单为 M1 准入条件；音效进 DoD；每个里程碑结束人工试玩对照「好玩」清单                       |
| **新变量 5 个，超控制变量原则**            | 里程碑分层（§4），每阶段只背 2–3 个；失败可归因到当阶段引入的那个                             |
| **PointerLock 在 headless 不可用** | `window.__fps` 钩子直接注入 yaw/pitch 与输入；页面保留「无锁拖拽模式」作为降级与可访问性选项      |
| **敌人卡墙 / 挤成一团**                | 竞技场为开阔场地；敌人用直线追击 + 前方短射线避障 + 相互排斥力；AI 与玩家共用 KCC 保证移动语义一致         |
| **射击命中判定在快速移动下不准**             | 用射线即时命中（hitscan），不做抛射物；固定步长 1/60，命中与物理同帧                         |
| **手感调不准（太飘/太钝）**               | 参数集中在 config.ts；M3 用 bot 扫参（TTK / 散布 / 后坐力回落），人工只在 2–3 组候选里裁决    |
| **音效在无头环境不可听**                 | 只自动验证「AudioContext 节点已创建 + 无报错 + 事件计数」；**听感必须人工验收**（明确标注该局限）     |
| **内容量失控**（02 曾在此崩塌）            | 上限：3 武器 / 3 敌人 / 5 波 / 1 竞技场；全部数据驱动，规模压到人工可逐条验收                  |
| **headless 下 FPS 不可信**         | 沿用 05 / 03 结论：性能指标只看 draw call / 三角面数 / 实体数，不记录 FPS              |
| **game-lab 无版本控制**             | 开工第一件事 `git init` + 提交基线（当前 `git status` 报 not a git repository） |
